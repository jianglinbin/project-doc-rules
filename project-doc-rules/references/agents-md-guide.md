# 阶段 1：规则层（AGENTS.md）生成指南

> 产出：项目根 `AGENTS.md`。硬上限 **150 行**——超行说明在重复规格或堆细节，回炉。

## 一、写作四纪律

1. **只管「怎么干活」，不管「干什么」**：规格内容（协议、架构、UI）不进本文件，只放一行引用。
2. **冲突优先级写死**：规格 > 规则；代码与规格冲突时先改规格再改代码。
3. **规则只增补不展开**：细则与决议细节归台账；本文件修订 = 增补条款或整段替换，不无限膨胀。
4. **每条规则可执行、可校验**：写「平台宏只准出现在 src/platform/」，不写「注意平台差异」。

## 三、通用基础规则库（默认全部写入，访谈确认后可裁剪）

以下条款与技术栈无关，是生产环境验证过的通用纪律。骨架「§0 基础工作规则」按此处条文生成；某条确实不适用的项目，访谈时说明后删除，不凑数。

| # | 规则 | 写入 AGENTS.md 的条文 |
|---|---|---|
| 1 | 未确认不动工 | 动手前必须有已确认的开工依据（规格文档条款或用户的明确拍板）；方案未确认前不写实现代码，先出方案待确认。 |
| 2 | 规格先行（指变更顺序，非优先于规则） | 任何行为变更**先改规格、再改代码**；代码与规格冲突以规格为准。规则层全程有效，管的是「怎么干活」——与规格是分工关系，不是谁先谁后。 |
| 3 | 单一真值 | 版本号、配置、状态等关键信息只有一个权威来源，其余位置只引用、禁止复制第二份。 |
| 4 | 先提交再推送 | 任何远程推送之前，改动必须已提交本地库；顺序不可倒置。 |
| 5 | 机器护航 | 可机器校验的纪律一律脚本化（退出码判定），不靠人眼自觉。 |
| 6 | 产物与源分离 | 构建产物、第三方依赖、日志不进版本库；`.gitignore` 显式列出清单。 |
| 7 | 零警告门槛 | 编译/构建出现任何警告即视为未通过，先修复再继续；确需豁免时显式声明并记台账。 |
| 8 | 实改动即记账 | 每次实质改动完成后立即记台账，收尾必跑校验脚本。 |
| 9 | 无明确指令不执行 | 用户明确指令是执行的前置授权；无指令不执行、不发布；指令含糊时先确认再动手。 |
| 10 | 推送由用户主动要求 | Agent **不推送、也不询问是否推送**：push 远程、新建/删除远程 tag、发布 Release 只在用户明确提出时执行；本地提交后停留在本地是正常状态。 |
| 11 | 本地标签只作回退，封版开版须用户确认 | 本地标签仅作阶段回退锚点（如 `rb/dN`），**不占用版本号、不随阶段递增**；封版与开版均须用户明确指令——封版冻结当前版本，封版 ≠ 开版：仅当封版后收到新开发需求才开新版本台账。 |
