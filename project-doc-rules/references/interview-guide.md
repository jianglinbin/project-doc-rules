# 访谈原语：设计树与待问边界轮询（阶段 0 与阶段 1 共用）

> 访谈的对象不是问题清单，而是一棵树。本文件只定义通用纪律；各阶段的树与题目定义在该阶段 reference 内。

## 一、设计树

- 先建树，再提问：节点 = 一个待拍板的决策；边 = 依赖关系（子决策的提问依赖父决策的答案）。
- 树来自对产出的拆解：产物需要哪些信息、哪些信息依赖哪些信息，就长成哪些节点与边。
- 题目内容以各阶段 reference 的清单为准，本文件不重复列题。

## 二、待问边界与轮询

- **待问边界** = 前置决策已全部落定、现在提问不需要猜测任何未听到答案的节点集合。
- 每轮把整个待问边界一次问完（编号 + 推荐答案），然后停下等待用户回答。
- 回答后重算边界：落定的决策向外推开边界、解锁下游问题；依赖本轮未决问题的提问归入后续轮次，不混入本轮。
- 禁止一次倾倒全部问题，也禁止逐条挤牙膏式提问。

## 三、问题格式

```
❓ Q1 - **标题**：问题正文（可含选项）
➡ 推荐：答案（依据：观察来源）
```

- 措辞让「是/同意」即接受推荐答案——用户可以一字回复扫完整轮。
- 推荐必须注明观察依据（事实自查结果或通用默认）；给不出依据就不设推荐，退回开放提问。

## 四、事实与决策二分

- **事实自己查**：项目名、版本号、目录结构、构建命令等凡环境可得的（读文件、跑命令、读既有文档），一律自查，禁止拿去问用户。
- **决策必须问**：取舍、偏好、命名、允许/禁止规则等没有客观答案的，逐条摆给用户并等待。
- 事实自查未返回时只挂起其下游决策，其余照问，不整轮阻塞。

## 五、完成判据与 TODO

- **访谈完成 = 待问边界清空**：树的所有分支都已访问，无任何静默假设残留。
- 边界清空后，把达成的共识向用户复述确认；**确认共识之前不得生成本阶段产物**。
- 用户明确表示稍后再答的问题记 TODO 占位（占位与收尾汇总规则见 SKILL.md 铁律）；**TODO 是兜底不是默认**——能问尽问，不主动跳过。

## 六、档位裁剪

| 档位 | 轮次 | 不变项 |
|---|---|---|
| full | 完整树、完整轮次（阶段 1 默认两轮） | 格式与完成判据不减 |
| lean | 两轮 | 同上 |
| minimal | 允许合并为单轮 | 编号+推荐答案格式不减，边界清空+共识确认不减 |
