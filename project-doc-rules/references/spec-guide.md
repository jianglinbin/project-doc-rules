# 阶段 2：规格层规范

> minimal 档不读本文件（简版条款见 SKILL.md）；full/lean 档先读 §零 生成项目方案；§一–§四 仅 full 档适用。

## 零、项目方案（docs/PROJECT_PLAN.md，full/lean 生成）

项目方案是**项目级唯一开工依据**（总体定位、目标、非目标、功能线、里程碑）；功能线级开工依据仍是各 `<FEATURE>_PLAN.md`。新建档项目由本阶段生成方案，既有项目已有同等文档则迁移映射、缺项访谈补齐。

**方案轮访谈**（遵照 interview-guide.md，一轮发出、边界清空后落盘）：

| # | 节点 | 问什么 | 推荐依据（自查） |
|---|---|---|---|
| P1 | 目标与非目标 | 项目要达成什么（可验证）、明确不做什么 | 定位 + README / 既有文档 |
| P2 | 功能线清单 | 有哪些功能线、优先级如何 | 目录结构 / 既有规划文档 |
| P3 | 里程碑与验收 | 分几步走、每步怎么算完成 | 功能线依赖关系 |

- 三题都只依赖根决策（项目定位），故同属一轮；用户答「是」即接受推荐。
- 落盘：从 `assets/templates/project-plan.md.tpl` 复制为 `docs/PROJECT_PLAN.md`，占位符 `{{PROJECT_NAME}}` 等按访谈答案项目化替换；台账流水记首条（初稿生成）。
- 用户确认定稿前状态为草案；AGENTS.md「唯一开工依据」指向本文件。
- **minimal 档不落盘**：目标与非目标一句话并入 AGENTS.md 引言，不建方案文档。

## 一、定位与产出

每条功能线（一次较大的开发战役：新模块、重写、大特性）一份规格文档，是该线的**唯一开工依据**。规则层引用它，不复制它。零散小修不需要规格，直接记台账。

**本阶段产出**（两步）：

1. 从 `assets/templates/spec-doc.md.tpl` 复制为项目 `docs/SPEC_TEMPLATE.md`，内容不改（结构、头部三件套、维护纪律均已内嵌模板，未来建规格时照模板实例化）。
2. 在 AGENTS.md「文档与命名」条款中加一行：`规格模板见 docs/SPEC_TEMPLATE.md，较大功能线先复制定稿后实施`。

## 二、命名（写进 AGENTS.md）

- 规划/实施方案：`<FEATURE>_PLAN.md`；协议/行为规格：`<X>_SPEC.md`。
- 放项目根（规格是开工依据，要显眼）；文件名 `UPPER_SNAKE_CASE`。

## 三、头部三件套（模板已含，讲解不落盘）

1. **状态行**——打开文件第一眼知道进展到哪；
2. **台账流水**——方案的每一次翻案都有据可查；
3. **既定约束**——已拍板事项防止后续会话重新发明方案。

冲突优先级必须出现在 AGENTS.md：**规格 > 规则；先改规格（并记台账）再改代码**。

## 四、维护规则（已内嵌模板头部注释，无需另落盘）

修订即记账；大改整体替换为 v2（旧版由台账兜底）；定稿封版后只读；规格不记流水账（过程取证进台账）。

写盘后进入阶段 3。
