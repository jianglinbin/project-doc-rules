# 阶段 2：规格层规范

> 仅 full 档读本文件；lean/minimal 档直接用 SKILL.md 路由表下方的简版条款，不读本文件。

## 一、定位与产出

每条功能线（一次较大的开发战役：新模块、重写、大特性）一份规格文档，是该线的**唯一开工依据**。规则层引用它，不复制它。零散小修不需要规格，直接记台账。

**本阶段产出**（两步）：

1. 从 `assets/templates/spec-doc.md.tpl` 复制为项目 `docs/SPEC_TEMPLATE.md`，内容不改（结构、头部三件套、维护纪律均已内嵌模板，未来建规格时照模板实例化）。
2. 在 AGENTS.md「文档与命名」条款中加一行：`规格模板见 docs/SPEC_TEMPLATE.md，较大功能线先复制定稿后实施`。

## 二、命名（写进 AGENTS.md）

- 规划/实施方案：`<FEATURE>_PLAN.md`；协议/行为规格：`<X>_SPEC.md`。
- 放项目根（规格是开工依据，要显眼）；文件名 `UPPER_SNAKE_CASE`。

## 三、头部三件套（模板已含，讲解不落盘）

1. **状态行**——打开文件第一眼知道进展到哪；
2. **台账流水**——方案的每一次翻案都有据可查；
3. **既定约束**——已拍板事项防止后续会话重新发明方案。

冲突优先级必须出现在 AGENTS.md：**规格 > 规则；先改规格（并记台账）再改代码**。

## 四、维护规则（已内嵌模板头部注释，无需另落盘）

修订即记账；大改整体替换为 v2（旧版由台账兜底）；定稿封版后只读；规格不记流水账（过程取证进台账）。

写盘后进入阶段 3。
